# v8unpack-accel 2.0.0

Дата: 29.09.2026. Основа — 1.0.0 (`../v1.0.0`). Все найденные ускорения распаковки v8unpack 1.2.13; результат
распаковки побайтно тот же, что у 1.0.0 и штатного v8unpack.

## Что нового

| Модуль | Что делает | Выключение |
|---|---|---|
| `v8unpack_fastbrace.py` | разбор скобочного формата через `json.loads`, необычные файлы — исходному автомату | `fastbrace` |
| `v8unpack_jsonwrite.py` | запись JSON своим сериализатором одной строкой, формат как у `json.dump` | `jsonwrite` |
| `v8unpack_organizer.py` | организатор без копирования `decode_stage_3`, неизменённое не перезаписывается | `inplace` |
| `v8unpack_accum.py` | склейки строк через список: base64, текстовые файлы, раскладка модулей | `accum` |
| `v8unpack_io.py` | вложенные контейнеры в памяти, кэш созданных каталогов | `io` |
| `v8unpack_fastparse.py` | + значения вне кавычек куском | `fastparse` |

Выключение: `set V8UNPACK_DISABLE=fastbrace,inplace` (через запятую). Первая строка вывода
`v8unpack_serial.py` / `run_unpack.py` / `v8unpack_resume.py` — версия и включённые ускорения.
Подробно по каждому изменению — `PATCHES.md`; список изменений — `../../../CHANGELOG.md`.

`io` +5%, `accum` ≈0 (на этом файле мало длинных модулей). Дерево во всех 35 прогонах одно и то же.

Машина замеров всё время загружена чужими процессами (60–100% CPU), поэтому сравнение идёт по CPU процесса.

всегда новое, при любой версии. Сверка сравнивает имена, CRC и байты записей.

## Установка в проект 1С

Скопировать `tools/*.py` в `tools\` проекта (все 12 файлов: модули подключаются из того же каталога).
После копирования сверить md5 с `MANIFEST.json` (sha256). Запуск — как раньше, см. `docs/raspakovka-v8unpack.md`.
Откат — файлы `../v1.0.0/tools`.

## Ограничения

- Проверено на v8unpack 1.2.13. После обновления v8unpack — `v8unpack_fastparse_check.py` на 400 файлах
  и полная распаковка контрольного файла со сравнением дерева (`bench/scripts/compare_tree.py`).
- Организатор без копирования работает, только когда temp и результат на одном томе; иначе копирует штатно.
- Пик памяти на УТ 11.5 — 947 МБ; у 1.0.0 на УТ он не замерялся. Вероятная причина — разбор в памяти вложенных
  контейнеров и крупных файлов целиком. На `.cfe` 3 МБ пик 2.0.0 и 1.0.0 одинаковый, десятки МБ.
- Серийный режим — одно ядро; параллелизм не входит.
